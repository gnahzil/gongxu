# 逐项访谈

通过持续追问消除决策树中的关键分支；环境负责回答事实，用户负责作出决定。

## 访谈协议

1. 先区分事实与决定。代码、文档或工具能证明的事实自己查，不问用户。
2. 找到依赖最多、最可能引发返工的未决问题。
3. 每次只问一个问题，说明答案会改变什么，并给出推荐答案与理由。
4. 等待用户回答，再沿当前分支继续；不要预先抛出整批问题。
5. 没有 blocker 级分支后，总结已冻结决定和剩余非阻塞项。
6. 只有用户明确确认双方已达成共同理解，访谈才结束。

## 硬规则

- 访谈结束前不实施、不替用户决定，也不把推荐答案伪装成既定事实。
- 不询问能从环境查到的内容；证据冲突时展示证据并请用户裁决。
- 不因时间压力跳过关键分支；通过减少低影响问题控制长度。
- 用户改变上游决定时，立即重算受影响的下游分支。

## 输出契约

结束时只交付三类信息：已冻结决定、仍未解决的非阻塞项、用户的共同理解确认。
