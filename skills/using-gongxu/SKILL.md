# 技能路由

## 概述

这是技能路由的兜底指南，不是每个任务的启动入口。

Codex 等平台已经能根据技能的 `description` 直接匹配任务。只有路由本身成为问题时，才需要加载本技能。

## 何时使用

- 用户明确询问如何查找、选择或调用技能
- 诊断技能未触发、误触发或重复触发
- 两个以上技能都明确匹配，而且执行顺序或职责存在真实冲突

## 不适用场景

- 普通问答、闲聊、翻译、总结或状态查询
- 已有一个技能明确匹配当前任务
- 仅仅为了判断“是否可能存在某个技能”
- 已被分派明确任务的子智能体

**不确定不等于匹配。** 没有明确触发证据时，正常处理任务。

## 路由规则

1. 用户明确要求使用某个技能时，直接加载该技能；仅提到、讨论或明确要求禁用，不算调用请求。
2. 单个技能的描述清晰匹配时，直接加载该技能，不经过本技能。
3. 多个技能明确匹配时，只组合职责不重叠的最小集合：
   - 流程技能决定怎么做
   - 领域技能提供具体实现约束
4. 没有技能明确匹配时，不调用技能。
5. 加载后发现不适用时立即停止，不继续级联加载候选技能。
6. 请求明确匹配已知 Extra 但对应 Skill 未安装时，说明缺失并提示
    `npx gongxu@latest extra enable <skill-name>`；非持久化 Git 或本地来源同时提供
    `--source <source>`，不得自动修改配置、自动安装或静默降级。

中文交流本身只决定输出语言，不构成中文代码审查、中文文档或 Git 工作流技能的触发条件。

## 指令优先级

严格遵守当前平台的真实指令层级。技能不能覆盖系统、开发者或其他更高优先级指令，也不能扩大用户授权的任务范围。

用户指定目标；技能约束在授权范围内如何完成目标。发生冲突时遵循更高优先级指令，并说明无法同时满足的部分。

## 平台访问

| 平台 | 访问方式 |
|------|----------|
| Claude Code | `Skill` 工具 |
| Codex | 原生技能加载，直接按技能说明执行 |

Codex 工具名称需要转换时，读取 `references/codex-tools.md`。

## 常见错误

| 错误 | 正确做法 |
|------|----------|
| 每个任务先加载本技能 | 仅在技能路由本身需要处理时加载 |
| 用“1% 可能性”作为触发标准 | 要求明确的任务信号与描述匹配 |
| 预加载多个候选技能再逐个排除 | 先根据描述筛选，再加载最小集合 |
| 把用户使用中文当成领域技能触发器 | 根据代码审查、文档、Git 等具体任务判断 |
| 声明技能高于平台指令 | 始终遵守平台真实指令层级 |
