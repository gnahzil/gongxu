# 格式化纪律

**触发场景：** 任何代码改动；IDE 自动 format / 保存时格式化 / 整理 import。

## 硬规则

- **禁止**对未在本期变更的旧代码做任何 format / 重排 import / 调整空格 / 改换行符。
- 如使用 IDE 自动 format，**必须仅作用于本期实际修改的代码块（hunk）**。
- 遇到 IDE 无法精确控制格式化范围的情况，**宁可保留原始格式不动**，也不要顺手 format 一片。

## 自检 checklist

- [ ] `git diff` 中是否只包含本期任务相关的改动？
- [ ] 有没有出现纯格式化的行（空格、换行、import 顺序）混入业务改动？
- [ ] 修改的文件里，未触及的函数 / 类是否保持原样？

## 反例

- ❌ "顺便 format 一下旁边几行" — 不可。
- ❌ "IDE 自动整理了 import" — 必须手动 revert 与本期无关的 import 变动。
- ❌ 一个 PR 里 80% 是格式化、20% 是业务改动 — 业务改动会被淹没在格式化噪音里。
