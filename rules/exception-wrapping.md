# 微服务异常包装与安全日志硬规则

基础设施异常不得穿透业务边界。若目标项目声明了异常类型和处理器约定，名称以
项目约定为准；默认仍必须保留以下行为：

1. 在业务边界把存储、缓存、消息、HTTP/RPC 等技术异常转换为统一业务异常。
2. 业务响应包含业务错误码和用户可理解的中文友好文案；未知异常由全局处理器返回统一中文兜底，不暴露原始 message、堆栈、SQL、表名或内部地址。
3. 包装时保留原异常为 cause/inner error，不吞异常。
4. 日志只允许项目批准的标量字段；敏感值按项目策略删除、掩码、不可逆摘要或截断。默认不得记录完整请求/响应、DTO、command、参数 map、header、body、cookie、凭据或 token。
5. 每条异常路径指定唯一堆栈日志所有者。包装层与全局处理器不得重复记录同一异常堆栈；非所有者只记录不含堆栈的必要状态。
6. 在状态中记录允许日志字段、脱敏策略和日志所有者；未声明时采用最小字段并禁止对象日志。
