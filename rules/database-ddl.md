# 数据库 DDL 安全规则

**触发场景：** 任何建表、改表、约束、索引或数据迁移。

1. 先确认目标数据库引擎、迁移框架、当前 schema 与项目既有命名和发布约定；目标项目约定优先。
2. 迁移必须有明确所有者、部署顺序、兼容窗口、回滚或前滚恢复方案，并说明不可逆步骤。
3. 根据真实查询、写入与数据分布论证主键、外键、唯一性、空值、默认值、约束和索引；不得套用其他引擎语法。
4. 涉及存量数据时，分离结构变更与数据回填，评估锁、容量、耗时、并发写入和旧版本兼容性。
5. 在目标引擎与迁移框架支持的安全环境验证生成 SQL、升级、回滚/恢复和数据约束；生产或破坏性验证必须由用户批准。
6. 把引擎版本、项目约定来源、风险、验证证据和重检条件写入当前状态。

若启用 `mysql-strict` profile，还必须读取
`rules/profiles/mysql-strict/database-ddl.md`；它在本规则之上增加项目特定的 MySQL
约束。
