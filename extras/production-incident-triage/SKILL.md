# 生产故障排查

## 1. 输入与授权

先确认：受影响操作、观察到的行为、示例化标识、开始/结束时间与时区、影响范围。
明确生产只读授权、允许访问的证据类型、禁止区域和报告受众。任何写入、恢复、重启、
数据修正、提权、付费查询或不可逆动作均不在本 skill 范围内，必须交由用户。

真实秘密、凭据、cookie、连接串和生产数据不得进入对话或公共报告。只请求最小必要
的脱敏标识，例如 `orderId=ORDER-EXAMPLE-001`。

## 2. 解析工作区与证据入口

按 `rules/workspace-paths.md` 解析工作区与 artifact root。依次从项目 context、仓库
配置和代码发现：

- source roots、模块边界、入口与依赖调用；
- 日志、trace、metrics、部署和变更记录的只读入口；
- datastore schema、审计记录和只读查询入口；
- 统一时间源、关联 ID、脱敏规则和证据保留边界。

使用当前可用的符号引用、结构搜索和文本搜索能力定位入口、调用方、错误路径和数据
写入点，不假设语言、框架、日志平台、追踪系统或数据库。能力不可用时记录缺口。

## 3. 时间线与证据收集

1. 把全部时间转换为项目统一时区，固定最小可解释时间窗。
2. 从入口沿代码、部署版本和依赖构建候选路径，标明事实与假设。
3. 在授权范围内收集只读日志、trace/metrics、发布事件和数据状态。
4. 用关联 ID、顺序、版本和时间交叉验证；不能由单一日志直接推导因果。
5. 数据查询必须来自真实 schema，限定字段、时间窗和行数。默认示例域使用订单与库存，
   如 `orders`、`inventory_reservation`，不得把示例 schema 当作目标项目事实。
6. 对缺失、冲突、采样或时钟偏差明确标注，并据此限制置信度。

## 4. 隐私与存储

原始日志、trace ID、查询结果、截图、内部 URL 和真实业务标识只保存到：

```text
<workspace-root>/.gongxu/triage-private/<case-id>/
```

该目录必须被忽略。面向提交的脱敏报告写到：

```text
<artifact-root>/triage/<case-id>.md
```

公共报告只包含最小、不可逆脱敏的摘录和示例标识，不包含内部地址或可复原的低熵
标识 hash。若无法安全脱敏，报告保持本地，不写公共文件，并仅记录 evidence gap。

## 5. 根因验证

证据收集完成后委托 `systematic-debugging`：

- 区分症状、近因、根因和促成条件；
- 为每个假设列支持证据、反证和最小只读验证；
- 不足时返回未知项，不以“最可能”替代事实；
- 改进建议区分防复发、可观测性和操作流程，不执行生产修复。

## 6. 报告结构

```markdown
# <Case ID> 故障排查报告

## 1. 摘要

- 影响：<脱敏摘要>
- 时间窗：<统一时区>
- 结论与置信度：<结论或未知>

## 2. 已确认事实

- <事实及脱敏证据指针>

## 3. 事件时间线

1. <时间>：<事件与来源>

## 4. 假设验证

- 假设：<内容>
    - 支持：<证据>
    - 反证/缺口：<证据>

## 5. 根因与促成条件

- <可验证结论；不足则写未知>

## 6. 建议与待办

- <建议、所有者和复核条件>

## 7. 隐私与证据缺口

- <脱敏方式、未采集证据和本地私有证据目录>
```

## 7. 完成门禁

- [ ] 生产访问有明确只读授权，未执行写操作。
- [ ] 时间窗、时区、版本和关联方法可复核。
- [ ] 根因由多源证据支撑，缺失证据限制了置信度。
- [ ] 公共报告已脱敏，原始证据仅在忽略目录。
- [ ] 无法安全脱敏时只保留本地报告。
